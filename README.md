# Industrial AI Data Pipeline

**Databricks · PySpark · Delta Lake · Anomaly Detection · Matplotlib**

A small, self-contained portfolio project demonstrating a complete industrial sensor data pipeline. Built to show practical familiarity with the Databricks / PySpark / Delta stack as used in industrial AI/ML engineering roles.

---

## 1. What this project is

An end-to-end data pipeline on synthetic industrial sensor readings from four machines. The pipeline moves data from a raw CSV through quality checking, cleaning, Delta Lake storage, feature engineering, and basic anomaly detection, producing visible quality evidence at each stage.

---

## 2. Why it exists

Evidence of practical understanding of the industrial data / AI stack (Databricks, PySpark, Delta Lake, sensor data, data quality) — the kind of stack used by companies such as NKT, Siemens, ABB, and others building industrial AI systems.

The project is deliberately kept small. It demonstrates the workflow, not production scale.

---

## 3. Pipeline architecture

```
data/raw/sensor_readings.csv
        │
        ▼
  PySpark CSV ingestion
        │
        ▼
  Data-quality inspection
  (row count, nulls, duplicates, out-of-range, machine IDs, timestamp validity)
        │
        ▼
  Cleaning
  (timestamp parse, dedup, range filter, imputation)
        │
        ▼
  Post-cleaning validation assertions
        │
        ▼
  Delta Lake (cleaned layer)
        │
        ▼
  Feature engineering
  (temp_z_proxy, pressure_deviation, vibration_risk, energy_per_vibration)
        │
        ▼
  Anomaly detection
  (rule-based: Z-score + pressure + vibration thresholds)
        │
        ▼
  Delta Lake (features + anomaly layer)
        │
        ▼
  Matplotlib visualisations
  (temperature time series, vibration time series, anomaly bar chart)
        │
        ▼
  Final quality summary + assertions
```

## 4. Dataset

**File:** `data/raw/sensor_readings.csv`  
**Generated by:** `src/generate_data.py`  
**Rows:** ~5,000 (synthetic)  
**Machines:** M-101, M-102, M-103, M-104  
**Frequency:** 10-minute intervals, August 2026  

**Fields:**

| Column | Type | Normal range | Notes |
|---|---|---|---|
| timestamp | string → timestamp | — | 10-min intervals |
| machine_id | string | M-101–M-104 | 4 machines |
| temperature_c | float | 60–90 °C | Varies by machine |
| pressure_bar | float | 4–7 bar | Nominal 5.2 bar |
| vibration_mm_s | float | 0–5 mm/s | Risk threshold: 4 mm/s |
| energy_kwh | float | 35–65 kWh | Per 10-min reading |

**Deliberately injected quality problems:**
- Missing values (~1% of sensor readings)
- Duplicate rows (3 exact duplicates)
- Out-of-range temperature values (too high / too low)
- Out-of-range pressure values (sensor saturation)
- Out-of-range vibration values (beyond physical limits)
- Null machine_id on a small number of rows
- Anomalous spikes (thermal, pressure, vibration) representing real plant events

**Data is entirely synthetic.** No real equipment data is used.

## 7. How to run in Databricks

**Requirements:** Databricks Community Edition or any workspace with Databricks Runtime 11.3 LTS or later (includes PySpark, Delta Lake, and Matplotlib).

1. **Upload the dataset**
   - Go to **Data → Add Data → Upload File**
   - Upload `data/raw/sensor_readings.csv`
   - Note the resulting path (typically `/FileStore/tables/sensor_readings.csv`)

2. **Import the notebook**
   - Go to **Workspace → Import**
   - Upload `notebooks/industrial_ai_data_pipeline.ipynb`

3. **Set the input path**
   - In the first code cell (Configuration), confirm `INPUT` matches the path from step 1

4. **Attach a cluster** and click **Run All**

5. **Inspect outputs**
   - Quality inspection tables
   - Cleaning statistics
   - Assertion pass messages
   - Delta table history
   - Feature table preview
   - Anomaly counts per machine
   - Three Matplotlib plots
   - Final quality summary

**Note:** The `delta.write` and `delta.read` calls require Delta Lake support (included in all Databricks runtimes). They will not work in a plain Jupyter environment without additional setup.

## 9. What is deliberately not included

This is a one-evening portfolio project. The following are out of scope by design:

- **Production-grade Delta medallion architecture** (Bronze / Silver / Gold layers)
- **Scheduled jobs / DLT pipelines** (Databricks Workflows)
- **ML model training** (IsolationForest, LSTM, etc.) — the anomaly detection is rule-based
- **Unity Catalog / data governance** — paths use `/FileStore/` not Unity Catalog volumes
- **Real equipment data** — all data is synthetic
- **Multi-node cluster tuning** — not relevant at this scale
